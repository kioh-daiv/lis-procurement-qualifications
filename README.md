# 臨床検査部門システム（LIS）クラウド化 — 案件受注のための資格要件

「法規制対応と技術要件ガイド」（[lis-cloud-compliance-guide](https://kioh-daiv.github.io/lis-cloud-compliance-guide/)）の姉妹版。法規制ガイドが「何を満たすか（規制遵守）」を扱うのに対し、本ガイドは「**受注する事業者になるために何を備えるか**」 ——組織の認証・人材の資格・事業形態の許可・入札資格・AWS パートナー認定の 5 レイヤーを整理したシングルページ HTML。

## 設計：3 つの必須度

全項目を必須度で色分けする。

- **必須ゲート**（赤）：これがないと土俵に立てない（入札参加不可、または事業形態上の許可がないと違法）
- **実質必須**（オレンジ）：法的な絶対要件ではないが選定の前提。ないと選ばれにくい
- **加点・差別化**（緑）：あると競争で勝てる。総合評価・プロポーザルの加点、医療業界での信頼・専門性の証明

## 構成（6 タブ）

- **全体像とロードマップ**：必須度マトリクス、3 つの構造的洞察、投資ロードマップ
- **組織の認証**：ISMS（JIS Q 27001:2023）/ ISO 27017・27018 / Pマーク / ISMAP / ASPIC医療情報認定 / HISPRO / JASA CS
- **人の資格**：医療系（医療情報技師・登録セキスペ・高度区分IPA・臨床検査技師・細胞検査士 等）＋ クラウド技術系（AWS Security-Specialty・CISSP・SAP・CKS 等）＋ 最小コア構成
- **事業形態の許可**：機能トリガー条件分岐（保管のみ＝許可不要／SaMD＝製造販売業許可／検査受託＝衛生検査所登録）
- **入札・調達資格**：全省庁統一資格・自治体名簿・ISMAP、公的 vs 民間の比較、準備リスト
- **AWS パートナー認定**：個人認定→組織ティアの積み上げ、HCLS Competency・Migration・FTR・共同営業

## 効いてくる 3 つの構造

1. 業許可は「機能トリガー」式（通常の LIS は薬機法業許可すべて不要）
2. 個人認定が組織の燃料（人を試験に通す投資→組織ティア→受注力）
3. 公的 vs 民間は別ゲーム（入札資格 vs 製品力）
